2.3 · Méthodes

PTQ ou QAT ?

PTQ

Post-entraînement

On convertit un modèle déjà entraîné. Rapide, simple, perte < 1–2 %.

QAT

Pendant l'entraînement

« Fake quantization » : le modèle s'habitue à l'Int8. Permet Int4, binaire.

# Quantification post-entraînement Int8
import tensorflow as tf

conv = tf.lite.TFLiteConverter.from_saved_model(dossier)
conv.optimizations = [tf.lite.Optimize.DEFAULT]
# données représentatives pour calibrer S et Z
conv.representative_dataset = donnees_repr
conv.target_spec.supported_ops = [
    tf.lite.OpsSet.TFLITE_BUILTINS_INT8]
conv.inference_input_type  = tf.int8
conv.inference_output_type = tf.int8

modele = conv.convert()
open("modele_int8.tflite", "wb").write(modele)
2.4 · Élagage

Couper les connexions inutiles

Beaucoup de poids sont proches de zéro : ils pèsent peu dans la décision.

Non structuré

Poids un par un · jusqu'à 90 % de compression · formats creux nécessaires

Structuré

Neurones, filtres entiers · gain réel en calcul · compatible matériel

Stratégie : 20 % par itération + fine-tuning, plutôt qu'un seul gros coup.

5.1 · Limites & défis

Ce qui reste difficile

Ressources limitées

Compromis permanent taille / précision / temps / énergie. TFLM : opérations limitées.

Fiabilité & données

Bruit, utilisateurs, position du capteur : un modèle bon en test peut dériver sur le terrain.

Faire évoluer le modèle

Entraînement hors de l'objet → mise à jour OTA. L'apprentissage sur l'appareil progresse (< 256 Ko), sans être généralisé.

Sécurité

Extraction ou modification du modèle, entrées piégées → flash chiffrée, démarrage sécurisé, OTA signée.

5.2 · Perspectives

Vers une intelligence distribuée

Le TinyML ne remplace pas le cloud : il le complète. Chaque niveau fait ce qu'il fait le mieux.
